# Fabric Capacity Metrics — Full Measure Catalog (raw TMSCHEMA_MEASURES dump)

**Obtained:** 2026-07-29, via a self-owned local/composite model in Power BI Desktop (Get Data →
Power BI semantic model → live connection to "Fabric Capacity Metrics" → "Make changes to this
model" → DAX Studio → `SELECT [Name], [Expression] FROM $SYSTEM.TMSCHEMA_MEASURES ORDER BY [Name]`).

**Result: EXTERNALMEASURE stubs on every single measure, identical to the original DAX Studio
session in Section 12.1.** This is a genuine, valuable NEGATIVE result — it confirms Option 1 from
GAPS-AND-ISSUES.md Section 6 (D1) is closed. The `EXTERNALMEASURE` protection is enforced at the
**base-model level itself**, not merely a property of which tool or connection path is used to
reach it. Building and owning your own composite model, then querying it directly, does not
bypass this — the new model's own schema still resolves every measure as a
`DirectQuery to AS - Fabric Capacity Metrics` stub, one layer of indirection deep, same as before.

**What this dump IS valuable for, despite the stubs:** it is the fullest, most complete measure
catalog this project has ever obtained — ~230 real measure names with real data types (DOUBLE,
INTEGER, STRING, BOOLEAN, DATETIME, CURRENCY), even though the DAX expression text behind each one
remains inaccessible. See GAPS-AND-ISSUES.md Section 12.12 for the curated findings pulled from
this list. This file is the full raw reference — consult it directly when you need to check
whether a specific measure name exists, its declared type, or its exact spelling/capitalization,
rather than re-deriving that from memory or an old export.
